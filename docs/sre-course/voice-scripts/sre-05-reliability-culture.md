## Scene 2 · How bad news travels: Westrum's three types

chapter: —

> ⟪page l05_p02⟫ ကိုမင်း ပြောရဲမလား ဆိုတာက သူ့ သတ္တိထက်၊ အရင်က မေးခွန်း မေးခဲ့တဲ့သူတွေ ဘာဖြစ်ခဲ့လဲ ဆိုတာပေါ်မှာ ပိုမူတည်ပါတယ်။ လူမှုဗေဒ ပညာရှင် Ron Westrum က သတင်းဆိုး ယူလာတဲ့သူကို ဘယ်လို ဆက်ဆံလဲ ဆိုတာနဲ့ အဖွဲ့အစည်း ယဉ်ကျေးမှုကို သုံးမျိုး ခွဲပြခဲ့ပါတယ်။
> ပထမ pathological အဖွဲ့မှာ အာဏာကို ဦးစားပေးလို့ သတင်းဆိုး ယူလာသူကို နှုတ်ပိတ်ခိုင်းပါတယ်။ ဒုတိယ bureaucratic အဖွဲ့မှာ စည်းမျဉ်းကို ဦးစားပေးလို့ သတင်းက တန်းစီပြီး အလှည့်စောင့်ရပါတယ်။ တတိယ generative အဖွဲ့မှာတော့ ရလဒ်ကို ဦးစားပေးလို့ သတင်းဆိုး ယူလာသူကို ကျေးဇူးတင်ပြီး ချက်ချင်း ဖြေရှင်းပါတယ်။
> software delivery ကို နှစ်စဉ် လေ့လာတဲ့ DORA သုတေသနကလည်း အဖွဲ့တစ်ခု generative ဘက် ရောက်လေ software ကို ပိုမြန်မြန်၊ ပိုစိတ်ချရအောင် ထုတ်နိုင်လေ ဖြစ်တာကို တွေ့ထားပါတယ်။ မသီရိက ကိုနေလင်းကို ပြတဲ့ အထောက်အထားလည်း ဒါပါပဲ။

## Scene 4 · What a reliability culture does

chapter: —

> ⟪close board⟫ ⟪page l05_p03⟫ reliability ကို တန်ဖိုးထားတဲ့ ယဉ်ကျေးမှုမှာ နေ့စဉ် အလေ့အထ သုံးခု ရှိပါတယ်။ ရာထူးကြီးသူ ထင်တာထက် data နဲ့ user ရဲ့ အမြင်ကို ကြည့်ပြီး ဆုံးဖြတ်တယ်၊ သိတာကို ကိုယ့်အဖွဲ့ထဲမှာပဲ မသိမ်းဘဲ တခြား အဖွဲ့တွေကို မျှပေးတယ်၊ တစ်ခုခု ပျက်ရင်လည်း အပြစ်ရှာစရာ မဟုတ်ဘဲ သင်ယူစရာ အဖြစ် ကြည့်ပါတယ်။
> ဒီ အလေ့အထတွေက အခြေခံ နှစ်ခုပေါ်မှာ ရပ်တည်ပါတယ်။ ပထမက ဘယ်လောက် စိတ်ချရရင် လုံလောက်လဲ ဆိုတာကို user တွေက ဆုံးဖြတ်တာပါ။ ဒုတိယက reliability အလုပ်ကိုလည်း feature အသစ်လိုပဲ ချီးကျူးပြီး ရာထူးတိုးတဲ့အခါ ထည့်တွက်တာပါ။ ဥပမာ နောက် သုံးလပတ် ဆုပေးပွဲမှာ Top-up ရဲ့ SMS provider အရန် အလုပ်ကို rewards screen အသစ်နဲ့ ဘေးချင်းယှဉ်ပြီး ချီးကျူးခဲ့ပါတယ်။
> ဘယ် tool တွေ သုံးလဲ ဆိုတာကလည်း အလေ့အထကို ပြောင်းစေပါတယ်။ ဥပမာ ဘယ်သူမှ မကြည့်တဲ့ tool ငါးခုထက် အဖွဲ့တိုင်း အတူ ကြည့်တဲ့ dashboard တစ်ခုက ပိုအသုံးဝင်ပါတယ်။

On screen:

- l05_p03 (K4): ယဉ်ကျေးမှုက ဘာလုပ်လဲ | data နဲ့ user အမြင်နဲ့ ဆုံးဖြတ် | သိတာကို အဖွဲ့တွေကြား မျှ | ပျက်တာကို သင်စရာ အဖြစ် ကြည့်

## Scene 5 · Hero loop vs learning loop

chapter: ညဘက် hero

> ⟪close page⟫ ⟪board B2 step 1⟫ Padauk ရဲ့ နောက်ပြဿနာက merchant တွေဆီ ငွေလွှဲတဲ့ settlement job ကြားမှာ ရပ်သွားရင် ပြန် run တတ်တာ ကိုအောင် တစ်ယောက်တည်း ဖြစ်နေတာပါ။ job ရပ်တာက merchant တွေကို ထိခိုက်နေလို့ ချက်ချင်း ဖြေရှင်းရမယ့် ပြဿနာ၊ incident ပါ။ incident ဖြစ်တိုင်း ကိုအောင်က ညဘက် ထပြင်ပေးတော့ အားလုံးက hero လို့ ချီးကျူးကြပါတယ်။
> ဒါပေမဲ့ ဘယ်လို ပြင်လဲ ဘယ်မှာမှ ရေးမထားလို့ ထပ်ဖြစ်တိုင်း သူ့ကိုပဲ ပြန်နှိုးရပါတယ်။ ဒီလို လူ တစ်ယောက်ရဲ့ ညဘက် ကြိုးစားမှုကို အားကိုးပြီး system ကို ရပ်တည်အောင် ထားတာကို hero antipattern လို့ ခေါ်ပါတယ်။ သင်္ကြန်မှာ ကိုအောင် ဇာတိ ပြန်သွားတုန်း job ရပ်သွားတော့ merchant တွေ ငွေရတာ တစ်ရက် နောက်ကျသွားပါတယ်။
> ⟪board B2 step 2⟫ ဒီတစ်ခါတော့ မသီရိက blameless review တစ်ခုကို ဦးဆောင်ပြီး ကိုနေလင်းကိုလည်း ဖိတ်ပါတယ်။ blameless ဆိုတာ lesson 2 က postmortem လိုပဲ ဘယ်သူ့ အပြစ်လဲလို့ လူကို မရှာဘဲ system နဲ့ လုပ်ငန်းစဉ်ထဲက အားနည်းချက်ကို ရှာတာပါ။ review ကနေ အဆင့်လိုက် ရေးထားတဲ့ runbook ထွက်လာပြီး၊ ပြဿနာ တက်ရင် တုံ့ပြန်ရမယ့် on-call တာဝန်ကိုလည်း အလှည့်ကျ ခွဲယူလိုက်တော့ လူတိုင်း ပြင်တတ်လာပြီး incident တွေလည်း နည်းလာပါတယ်။
> ⟪board B2 step 3⟫ ဒါပေမဲ့ ညဘက် ကယ်တင်တာကိုပဲ ဆက်ချီးကျူးနေရင်၊ အိပ်ရေးပျက်ပြီး အချိန်ပို လုပ်တာက တကယ့် အလုပ်ပဲလို့ အဖွဲ့တစ်ခုလုံး သင်ယူသွားပြီး၊ hero ကိုယ်တိုင်လည်း burnout ဖြစ်တတ်ပါတယ်။

- B2 step (1), cleared (red row, two-line boxes): incident → ကိုအောင် / ညဘက် ပြင် → ဘာမှ / မရေးထား → incident, circled ထပ်ဖြစ်

## Scene 6 · Two questions from Padauk's first review

chapter: Blameless review

> ⟪close board⟫ ⟪page l05_p04⟫ review မှာ ကိုအောင် အရင် ညတစ်ညက မနက် 2 နာရီမှာ check တစ်ခုကို ကျော်ခဲ့တာ ပေါ်လာပါတယ်။ အရင်ဆိုရင် ဘာလို့ ကျော်တာလဲလို့ မေးမှာပါ။ မသီရိကတော့ screen မှာ ဘာပြနေလဲလို့ မေးပါတယ်၊ အဖြေက check က အရမ်းကြာပြီး screen ကလည်း ပြီးပြီလို့ ပြနေတာပါ။ ဘယ်သူ ခွင့်ပြုခဲ့လဲလို့ မမေးဘဲ၊ job ကို ပြန် run ဖို့ ဘာလို့ လမ်း တစ်ခုတည်းပဲ ရှိနေရတာလဲလို့လည်း မေးပါတယ်။
> ဒီလို မေးတာက local rationality ဆိုတဲ့ အမြင်ကြောင့်ပါ။ လူတစ်ယောက် လုပ်ခဲ့တာက အဲဒီအချိန်၊ အဲဒီ အချက်အလက်နဲ့ဆိုရင် သူ့အတွက် အဓိပ္ပာယ် ရှိခဲ့တယ်လို့ မြင်တာပါ။ ကိုအောင်အတွက် အဓိပ္ပာယ် ရှိခဲ့ရင် နောက်လူအတွက်လည်း ရှိမှာမို့ ပြင်ရမှာက လူ မဟုတ်ဘဲ screen ပါ။
> ဒါပေမဲ့ blameless ဆိုတာ ဘယ်သူမှ တာဝန်မရှိဘူးလို့ မဆိုလိုပါဘူး။ review က owner နဲ့ ရက်စွဲ ပါတဲ့ လုပ်စရာတွေနဲ့ ပြီးရပါတယ်၊ ဥပမာ runbook ကို ကိုအောင်နဲ့ မသီရိ နောက်တစ်ပတ်အတွင်း ရေးမယ် ဆိုတာမျိုးပါ။ အပြစ်မပေးပေမဲ့ တာဝန်ယူမှုကို ထိန်းထားတဲ့ ဒီ ယဉ်ကျေးမှုကို just culture လို့ ခေါ်ပါတယ်။
