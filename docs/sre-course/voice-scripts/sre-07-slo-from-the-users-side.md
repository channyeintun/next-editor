## Scene 2 · Lie 1: where we measured

chapter: ဘယ်နေရာမှာ တိုင်းခဲ့လဲ

> ⟪close page⟫ ⟪board B1 step 1⟫ မသီရိက နေ့လယ်စာ မှာတဲ့ လမ်းကြောင်းကို ဆွဲကြည့်ပါတယ်။ user က app ကနေ ငွေချေရင် payment service က ငွေဖြတ်ပြီး order service ကို ငွေရပြီလို့ ပြန်ခေါ်ပြောရပါတယ်၊ ဒီလို ပြန်ခေါ်တာကို callback လို့ ခေါ်ပါတယ်။ callback ရောက်မှ order က ဆိုင်ဆီ ရောက်ပြီး app မှာ ပြေစာ ပေါ်တာပါ။ SLO တွေကတော့ service တစ်ခုချင်းအလိုက်ပဲ ရှိပါတယ်။
> ⟪board B1 step 2⟫ အဲဒီနေ့က callback တွေ error မပြဘဲ တိတ်တိတ်လေး ပျောက်နေခဲ့ပါတယ်။ payment service က ငွေဖြတ်တာ အောင်မြင်နေလို့ အစိမ်းရောင်၊ order service ကလည်း ရောက်လာတဲ့ request တွေကို အကုန် လုပ်ပေးနေလို့ အစိမ်းရောင်ပါပဲ။ ရောက်မလာတဲ့ request ကိုတော့ fail လို့ ဘယ်သူမှ မရေတွက်ပါဘူး။ ဒါကြောင့် SLO တိုင်း အစိမ်းရောင် ဖြစ်နေပေမဲ့ user ကတော့ ငွေပေးပြီးသားနဲ့ ဗိုက်ဆာဆာ စောင့်နေရတာပါ။
> ⟪board B1 step 3⟫ home page ပွင့်လား မိနစ်တိုင်း စစ်တဲ့ check ကလည်း လမ်းကြောင်းရဲ့ အစလေးကိုပဲ စစ်လို့ OK ပဲ ပြနေခဲ့ပါတယ်။ ဒါကြောင့် မသီရိက test wallet နဲ့ test ဆိုင်ကို သုံးပြီး order တစ်ခုကို user လို အစအဆုံး မိနစ်တိုင်း မှာကြည့်တဲ့ synthetic test order ကို ထည့်ပါတယ်၊ ပြေစာ မပေါ်ရင် fail ဖြစ်လို့ user တွေ မတိုင်ခင် သိရပါမယ်။

- B1 step (2): callback ပျောက် (red strike on the arrow between payment and order, red label under it)

## Scene 5 · What only the phone sees

chapter: ဖုန်းကပဲ မြင်တာ

> ⟪page l07_p04⟫ တချို့ ပြဿနာတွေကို server က ဘယ်တော့မှ မမြင်ရပါဘူး။ app crash ဖြစ်တာ၊ လိုင်းပြတ်တာ၊ ခလုတ် နှိပ်လို့ ဘာမှ မဖြစ်တာတွေကို user ရဲ့ ဖုန်းကပဲ မြင်လို့ ဖုန်းဘက်ကနေ တိုင်းတဲ့ client-side SLO လည်း လိုပါတယ်။ ဒါပေမဲ့ ဖုန်းက data မှာ ရှောင်လို့မရတဲ့ နောက်ခံ fail တွေ အမြဲ ပါပါတယ်။
> ⟪page l07_p04b⟫ ဥပမာ Eats rider တွေက ဈေးပေါတဲ့ ဖုန်းနဲ့ အားနည်းတဲ့ mobile data ကို သုံးလို့ ပုံမှန် နေ့တွေမှာတောင် request 3 ရာခိုင်နှုန်းလောက် fail နေပါတယ်။ request တွေကို တိုက်ရိုက် ရေတွက်ရင် ပစ်မှတ်ကို 97 ရာခိုင်နှုန်းအောက် လျှော့ထားရပြီး budget က အရမ်း ကျယ်သွားလို့ တကယ့် outage မှာတောင် page ဝင်မလာနိုင်တော့ပါဘူး။
> ⟪page l07_p04c⟫ ဒါကြောင့် rider app မှာ တစ်မိနစ်အတွင်း fail တာ 5 ရာခိုင်နှုန်း ကျော်မှ bad minute လို့ ရေတွက်ပါတယ်။ ဒီတော့ ပုံမှန် မိနစ်တွေက budget ကို မသုံးတော့ဘဲ rider တွေ တကယ် ဒုက္ခရောက်တဲ့ မိနစ်တွေကပဲ သုံးလို့ ပစ်မှတ်ကို တင်းတင်း ထားနိုင်ပါတယ်။
> ⟪page l07_p04d⟫ ဖုန်းဘက်က ပြဿနာကို ပြင်ရင်လည်း app store ကနေ user တွေ update လုပ်တဲ့အထိ ရက်နဲ့ချီ စောင့်ရပါတယ်။ ဖုန်းက data ကလည်း နောက်ကျပြီး ရောက်တတ်သလို ဘယ်သူမဆို ခေါ်လို့ရတဲ့ public endpoint ကနေ ကိုယ် မထိန်းနိုင်တဲ့ device တွေဆီက လာတာမို့ ယုံဖို့ သတိထားရပါတယ်။
> ဒါကြောင့် SLI တစ်ခုချင်းကို အဖွဲ့တိုင်း ယုံတဲ့ အဓိပ္ပာယ် တစ်ခုတည်း သတ်မှတ်ပြီး မျှသုံးတဲ့ SLO tool တစ်ခုထဲမှာ ထားပါ၊ ဒါမှ ကိန်းဂဏန်းကို ငြင်းမနေဘဲ ပြင်ကြမှာပါ။
